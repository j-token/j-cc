# j-cc

Claude Code에서 Claude가 **명령어로 파일을 읽거나, 오래 걸리는 명령어를 기다리거나, 사용자 지침을 읽지 않고 작업하는** 문제를 줄이는 플러그인입니다. 외부 모델이나 API 키 없이 Claude Code 안에서만 동작합니다.

[English](README.md)

## 이런 문제를 해결합니다

### 1. 명령어로 파일을 읽다보니 필요없는 내용이 추가됨

Claude가 `cat`, `grep -r`, `find` 같은 명령어로 파일을 보고 찾습니다. 이러면 필요없는 출력까지 컨텍스트에 들어가고, 명령어로 수정한 내용은 `/rewind`로 되돌릴 수 없습니다.

j-cc는 명령어로 파일을 보기·검색·쓰기·수정하는 호출을 막고 Read, Grep, Glob, Write, Edit를 쓰도록 안내합니다. 범위 없이 Read하면 500줄, Grep은 100개까지만 돌려줍니다.

- 셸 100회당 파일 보기 **8.0 → 3.3번**, 검색 **9.2 → 1.8번**

### 2. 명령어로 인해 세션이 계속 멈춰있음

`npm test`가 5분 걸리면 Claude도 끝날 때까지 5분 동안 아무것도 하지 못합니다.

j-cc에서는 명령어를 `exec` 도구로 실행합니다. exec는 최대 30초 안에 그때까지 나온 출력을 돌려주고, 명령어는 백그라운드에서 계속 실행됩니다. 끝나면 알림이 오기 때문에 그동안 Claude는 다른 작업을 합니다.

- 60초 넘게 붙잡힌 명령이 셸 1,000회당 **28.6 → 11.5번**, 셸 1회당 대기 **8.8초 → 4.5초**

### 3. 명령어로 인해 무한루프에 갇혀버림

로그를 보려고 `tail -f`를 실행하거나 `while true; do ...; sleep 60; done` 같은 루프를 돌리면 명령어가 끝나지 않아서 세션도 같이 멈춥니다.

j-cc는 이런 명령어를 막고 로그는 Monitor로, 반복 작업은 `/loop`나 `CronCreate`로 하도록 안내합니다.

### 4. 사용자 지침과 스킬을 읽지 않고 작업을 완료함

CLAUDE.md에 "커밋 전에 테스트를 돌려라"라고 적어 둬도 테스트 없이 작업을 완료했다고 보고합니다. 작업에 맞는 스킬이 있어도 스킬을 쓰지 않고 직접 처리합니다.

j-cc는 시스템 프롬프트에 아래 규칙을 넣습니다.

1. 사용자 지침이 기본 동작보다 우선
2. 작업 전에 스킬 목록부터 확인
3. 완료 보고 전에 가장 좁은 검사 실행

- 마지막 수정 뒤 검사 없이 끝난 코드 수정 턴 **14.5% → 6.7%**

### 5. 한국어로 대화하는데 중간 메모만 영어로 나옴

`language`를 한국어로 설정해도 영어로 된 도구 출력을 읽은 직후에는 짧은 메모가 영어로 나옵니다.

j-cc는 도구 결과와 중간 알림마다 응답 언어를 다시 알려 줍니다. 그래도 응답이 거의 영어로 나오면 CC 내부 모델이 설정한 언어로 썼는지 판정하고, 아니면 토스트로 알린 뒤 다음 턴에 경고를 붙입니다.

> 서브에이전트도 시작할 때 같은 규칙을 받습니다. 스킬·MCP 안내가 길면 잘라서 컨텍스트를 줄입니다.

## exec와 poll로 명령어 실행

j-cc는 포그라운드 Bash·PowerShell 호출을 막고, Claude가 이 두 도구로 명령어를 실행하게 합니다.

| 도구 | 하는 일 |
|---|---|
| `exec` | 명령어를 백그라운드로 실행하고 **최대 30초**(기본 10초) 안에 돌아옵니다. 그 안에 끝나면 종료 코드와 출력을, 아직 실행 중이면 그때까지의 출력과 `session_id`를 줍니다. 명령어가 끝나면 알림이 옵니다. |
| `poll` | 실행 중인 명령어의 출력을 최소 5초, **최대 5분**까지 기다리고, 명령어가 끝나면 바로 돌아옵니다. `terminate: true`로 멈출 수 있고, `session_id` 없이 부르면 실행 중인 명령어 목록을 보여 줍니다. |

**예: 3분 걸리는 테스트**

```
exec  "npm test"      → 10초 뒤: 지금까지 출력 + session_id 3   (테스트는 계속 실행)
Read / Edit ...       → 그동안 다른 파일을 읽고 고침
(알림) session 3 종료 → 결과를 보고 다음 단계로
```

- poll은 결과가 꼭 필요할 때만 씁니다. 다른 작업 없이 poll만 반복하면 거절합니다.
- exec나 poll이 기다리는 중에 메시지를 보내면 그때까지의 출력을 들고 바로 돌아오고, Claude가 메시지를 읽습니다. Claude Code는 턴 도중에 보낸 메시지를 도구 결과가 돌아올 때만 Claude에게 넘기기 때문에, 원래는 exec 뒤에서 최대 30초, poll 뒤에서 최대 5분을 기다렸습니다. 명령어는 계속 실행됩니다. `claude -p`에서는 메시지가 도구 결과 뒤에야 훅에 도착해서 적용되지 않습니다.
- 동시에 16개까지 실행할 수 있고, 출력은 기본 20,000자에서 앞뒤를 남기고 자릅니다.
- 실행할 때마다 새 셸이고 stdin이 닫혀 있어서 입력을 기다리는 대화형 명령어는 쓸 수 없습니다.

## 설치

```
/plugin marketplace add j-token/j-cc
/plugin install j-cc@j-cc
```

Claude Code 2.1.301 이상이 필요합니다(hooks module API).

j-cc는 작업 흐름을 돕는 도구이고 **보안 경계가 아닙니다.**

**회사·조직이 관리하는 Claude Code라면** 직접 설치한 플러그인이 시스템 프롬프트와 대화에 붙는 안내 문구를 고칠 수 없어서 일부만 동작합니다.

- 동작함: 1~3번(명령어 차단, exec, 무한루프 차단), Read·Grep 출력 제한, 도구 결과마다 붙는 응답 언어 알림과 언어 이탈 경고
- 동작 안 함: 4번 규칙(지침 우선, 스킬 먼저, 완료 전 검사), Claude in Chrome 섹션 줄이기, `language` 설정 문구 보강, 중간 알림에 붙는 응답 언어 알림, 스킬·에이전트 목록 줄이기, MCP 안내 자르기와 지연 도구 목록 묶기, `total_tokens_reminder` 제거, exec가 이미 보고한 명령어의 중복 완료 알림 제거

## 측정 근거

위 수치는 2026-09-10 ~ 11-02의 대화형 CLI 세션 기록 3,581개에서 뽑았습니다. j-cc를 쓰기 시작한 10월 16일 이후의 Opus 메인 세션을 j-cc 사용(38개)과 미사용(120개)으로 나눠 비교한 값입니다.

세션마다 작업이 달라서 차이를 전부 j-cc 효과로 볼 수는 없습니다. 조사 방법, 전체 표, 근거 논문([arXiv:2609.00006](https://arxiv.org/html/2609.00006v1))은 [docs/harness-engineering-evidence.md](docs/harness-engineering-evidence.md)에 있습니다.

## 설정

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `modelJudge` | `true` | 규칙으로 판단하지 못한 백그라운드 명령어, 우회 이유, 응답 언어 이탈을 CC 내부 모델(Haiku)로 판정합니다. 끄면 결정적 규칙만 씁니다. |
| `blockChaining` | `false` | 켜면 따옴표 밖의 `&&`, `\|\|`, `;`로 명령어를 이은 호출을 막습니다. |

## 명령어가 잘못 막혔을 때

규칙이 정확하지 않다 보니 꼭 필요한 명령어도 막힐 수 있습니다. 이때는 이유를 적은 주석을 붙여서 다시 실행합니다.

```
grep -c MAGIC app.exe # j-cc:allow: Grep 도구는 바이너리 파일 안을 검색하지 않음
```

<details>
<summary>우회 판정 방식</summary>

- 규칙에 막혔을 명령어에 주석이 붙어 있으면 CC 내부 모델(Haiku)이 막은 규칙, 명령어, 이유를 보고 명령어가 정말 필요한지 판정합니다.
- 이유가 막연하거나 편의 때문이거나 안내한 도구로 할 수 있는 작업이면 `Bypass rejected`로 막고, 대신 쓸 도구나 방법을 한 문장으로 알려 줍니다.
- 판정은 명령어별로 기억합니다.
- 규칙에 막히지 않는 명령어는 검토하지 않습니다. Bash·PowerShell 호출이면 결과에 주석이 필요 없었다고 알려 줍니다. 주석을 붙여도 포그라운드 Bash는 허용되지 않습니다.
- `modelJudge`를 껐거나 모델이 답하지 못하면 주석을 믿고 통과시킵니다.
- 이전 플러그인 표식 `# use-right-tool:allow:`도 인식합니다.

</details>

## 자세한 동작

<details>
<summary>영역별 동작 전체</summary>

| 영역 | 내용 |
|---|---|
| 파일은 전용 도구로 | 명령어로 파일을 보기·검색·쓰기·수정하는 호출을 막고 Read, Grep, Glob, Write, Edit로 안내합니다. |
| 명령어는 exec로 | 포그라운드 Bash·PowerShell 호출을 막고 `mcp__j-cc__exec`로 안내합니다. exec는 명령어를 Bash·PowerShell 백그라운드 작업으로 넘기고, 명령어가 끝나거나 `yield_time_ms`(기본 10초, 최대 30초)가 지나면 그때까지 나온 출력을 돌려줍니다. 끝나지 않은 명령어는 계속 실행되고, 끝나면 완료 알림이 옵니다. `mcp__j-cc__poll`은 출력을 더 기다리거나(최소 5초, 최대 5분) `terminate: true`로 작업을 멈춥니다. 직전 보고 뒤로 다른 작업 없이 부른 poll은 거절합니다. 동시에 실행할 수 있는 명령어는 16개까지입니다. `run_in_background: true`인 Bash·PowerShell은 그대로 실행합니다. |
| 무한루프 차단 | `tail -f`, `watch`, `logs -f` 같은 스트림 따라가기, 무한 루프, 반복마다 1분 이상 쉬는 루프를 막고 Monitor, `/loop`, `CronCreate`로 안내합니다. Bash·PowerShell의 `run_in_background` 명령어 중 규칙으로 판단하지 못했고 루프·대기·서버 단서가 있는 명령어는 CC 내부 모델(Haiku)이 판정하고, `endless`로 판정하면 막습니다(`modelJudge`). exec가 없는 서브에이전트의 포그라운드 셸에서는 dev 서버, 폴링 루프, 5초 이상 대기도 막습니다. |
| 명령어 체이닝 | 기본으로는 막지 않습니다. `blockChaining`을 켜면 따옴표 밖의 `&&`, `\|\|`, `;`로 이은 호출을 막습니다. |
| 프롬프트 보강 | 시스템 프롬프트에 세 섹션을 추가합니다. `# User workflow first`는 CLAUDE.md 우선, 스킬 먼저 확인, 완료 보고 전에 가장 좁은 검사 실행을 안내합니다. `# Tool routing`은 필요한 도구가 없으면 셸보다 ToolSearch로 먼저 찾게 하고, `# Shell commands (j-cc)`는 exec 사용법을 알려 줍니다. 스킬 목록 머리말에는 "작업 전에 목록과 대조해 맞는 스킬을 먼저 부르고, 키워드만 겹치면 부르지 않는다"는 규칙을 넣습니다. Bash·PowerShell 설명 끝에는 위 차단 규칙을 적습니다. PowerShell은 ToolSearch 뒤로 미루고, Monitor는 처음부터 불러옵니다. |
| 응답 언어 | `language` 설정이 도구 호출 사이의 짧은 메모에도 적용된다고 덧붙입니다. 메인 세션의 도구 결과와 대화 중간 알림, 사용자가 보내지 않은 프롬프트에도 응답 언어를 다시 알립니다. 응답이 거의 영문자이면(코드·경로·URL을 빼고 20자 이상) CC 내부 모델이 설정 언어로 썼는지 판정합니다. 아니라고 판정하면 토스트로 알리고 다음 도구 결과나 프롬프트에 경고를 붙입니다(`modelJudge`). |
| 서브에이전트 | 서브에이전트가 시작할 때 과제 끝에 파일 도구·exec·Monitor 규칙을 붙입니다. 이 경로로 규칙을 받지 못한 서브에이전트(fork 포함)는 첫 셸 결과에서 한 번 받습니다. 정의 파일의 `tools:`에 exec가 없는 에이전트는 포그라운드 셸을 막지 않습니다. j-cc를 쓴 세션에서도 서브에이전트는 셸 100회당 12.7 / 9.4번 명령어로 파일을 보고 검색했습니다(메인 세션의 4~5배). 메인 시스템 프롬프트가 서브에이전트까지 전달된다는 보장이 없어서 규칙을 따로 넣습니다. |
| 컨텍스트 줄이기 | 스킬·에이전트 목록의 설명을 첫 문장(최대 120자)으로 줄이고 중복을 뺍니다. MCP 서버 안내는 서버당 600자에서 자르고, 도구가 8개 이상인 MCP 서버는 지연 도구 목록을 한 줄로 묶습니다. `total_tokens_reminder`를 지우고 Claude in Chrome 섹션을 짧은 버전으로 바꿉니다. `limit` 없이 텍스트 파일을 Read하면 500줄까지만 읽고 나머지를 읽는 방법을 알려 줍니다. `head_limit` 없는 Grep은 결과를 100개로 제한합니다. |

</details>

## 제한

<details>
<summary>알려진 제한 전체</summary>

- 규칙이 정확하지 않아서 필요한 명령어를 막거나 막아야 할 명령어를 놓칠 수 있습니다.
- 서브에이전트에 exec가 있는지는 정의 파일에서 읽습니다. 프로젝트의 `.claude/agents/<이름>.md`를 먼저 보고, 없으면 `~/.claude/agents/`를 봅니다. 플러그인 에이전트는 exec가 있다고 봅니다.
- exec는 Bash 도구로 명령어를 실행해서 샌드박스를 켜면 그대로 적용될 것으로 보지만, 샌드박스를 켠 상태에서 직접 확인하지는 않았습니다. 2.1.316의 Windows 샌드박스는 기능 플래그 뒤에 있습니다. 서브에이전트처럼 Claude Code가 백그라운드 시간을 제한하는 곳에서는 그 한도(기본 10분)까지 끝나지 않은 작업이 Bash `run_in_background`와 똑같이 멈춥니다.
- exec나 poll이 기다리는 동안 Esc를 누르는 경우는 대화형 세션에서 확인하지 않았습니다.
- `blockChaining`을 켜면 체이닝 판별이 따옴표만 보는 단순한 방식이라 `for …; do …; done`, PowerShell `{ …; … }` 블록 안의 `;`도 막힙니다. 이런 스크립트는 scratchpad에 파일로 쓰고 그 파일을 실행하도록 안내합니다.
- 파일 보기와 다른 명령어를 이은 체인(`head f && wc -l f`)은 파일 보기 규칙에 걸리지 않습니다. 이 규칙은 호출 전체가 보기·검색뿐일 때만 막습니다.
- exec의 권한은 같은 명령어의 Bash/PowerShell 판정을 따릅니다. 그 판정이 `ask`이거나 auto mode 분류기가 Bash 판정을 내지 않아 거부한 경우에는 엔진이 exec 자체에 내린 판정을 그대로 씁니다. 그래서 auto mode에서는 분류기가 판단하고, 기본 모드에서 "항상 허용"을 고르면 그 규칙이 남습니다. exec 전체를 허용 규칙에 넣으면 Bash였다면 물었을 명령어도 묻지 않고 실행됩니다.
- exec가 부르는 Bash 호출은 권한을 다시 확인하지 않습니다. 같은 명령어의 Bash/PowerShell 판정을 따르는 exec 자신의 확인이 유일한 관문입니다. 다른 플러그인의 Bash 훅은 이 호출에도 적용됩니다. settings.json의 `Bash`/`PowerShell` PreToolUse 훅이 적용되는지는 확인하지 않았습니다. stdin이 닫힌 채 실행하므로 대화형 프롬프트는 쓸 수 없습니다.

</details>
