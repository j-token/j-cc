# j-cc

Claude Code에서 Claude 모델(특히 Opus 5.5)이 **전용 도구를 쓰고, 사용자 지침과 스킬을 따르고, 오래 걸리는 명령을 기다리지 않도록** 하네스를 조정하는 플러그인입니다. 외부 모델이나 API 키 없이 Claude Code 안에서만 동작합니다.

[English](README.md)

## 왜 필요한가

- 2026-09-10 ~ 11-02의 세션 기록 3,581개(대화형 CLI 세션만)에서, j-cc를 쓰기 시작한 10월 16일 이후 Opus 메인 세션을 j-cc 사용 여부로 나눠 비교했습니다. 세션마다 작업이 달라서 차이를 모두 j-cc 효과로 볼 수는 없습니다. 조사 방법, 전체 표, 변경의 근거로 삼은 논문([arXiv:2609.00006](https://arxiv.org/html/2609.00006v1))은 [docs/harness-engineering-evidence.md](docs/harness-engineering-evidence.md)에 있습니다.

| 지표 (Opus, 메인 세션) | j-cc (38) | 미사용, 10/16 이후 (120) |
|---|---|---|
| 셸 100회당 파일 보기 / 검색 | 3.3 / 1.8 | 8.0 / 9.2 |
| 셸 1,000회당 60초 넘는 포그라운드 명령 | 11.5 | 28.6 |
| 셸 1회당 포그라운드 대기 | 4.5초 | 8.8초 |
| 마지막 수정 뒤 검사 없이 끝난 코드 수정 턴 | 6.7% | 14.5% |

- j-cc를 쓴 세션의 서브에이전트는 여전히 셸 100회당 12.7 / 9.4번 셸로 파일을 보고 검색했습니다. 메인 세션의 약 4~5배이고 차단도 2배 넘게 당했습니다. 메인 시스템 프롬프트의 섹션이 서브에이전트에 닿는다는 보장이 없어서, 이제 서브에이전트는 시작할 때 규칙을 받습니다.

## 하는 일

| 영역 | 내용 |
|---|---|
| 파일은 전용 도구로 | 셸로 파일을 보기·검색·쓰기·수정하는 호출을 막고 Read, Grep, Glob, Write, Edit로 안내합니다. 잘못 막힌 명령은 이유 주석을 붙여 다시 실행할 수 있습니다([우회](#우회)). |
| 셸 명령은 exec로 | 포그라운드 Bash·PowerShell 호출을 막고 `mcp__j-cc__exec`로 안내합니다. exec는 명령을 Bash·PowerShell 백그라운드 작업으로 넘깁니다. 명령이 끝나거나 `yield_time_ms`(기본 10초, 최대 30초)가 지나면 그때까지 나온 출력을 돌려줍니다. 끝나지 않은 명령은 계속 돌고, 끝나면 완료 알림이 옵니다. `mcp__j-cc__poll`은 출력을 더 기다리거나(최대 5분) `terminate: true`로 작업을 멈춥니다. 직전 보고 뒤로 아무 일도 하지 않고 부른 poll은 거절합니다. 동시에 돌릴 수 있는 명령은 16개까지입니다. `run_in_background: true`인 Bash·PowerShell은 그대로 실행합니다. |
| 끝나지 않는 명령 차단 | `tail -f`, `watch`, `logs -f` 같은 스트림 따라가기, 무한 루프, 반복마다 1분 이상 쉬는 루프를 막고 Monitor, `/loop`, `CronCreate`로 안내합니다. Bash·PowerShell의 `run_in_background` 명령 중 규칙으로 판단하지 못했고 루프·대기·서버 단서가 있는 명령은 CC 내부 모델(Haiku)이 판정합니다. `endless`로 판정하면 막습니다(`modelJudge`). exec가 없는 서브에이전트의 포그라운드 셸에서는 dev 서버, 폴링 루프, 5초 이상 대기도 막습니다. |
| 명령 체이닝 | 기본으로 막지 않습니다. `blockChaining`을 켜면 따옴표 밖의 `&&`, `\|\|`, `;`로 이은 호출을 막습니다. |
| 프롬프트 보강 | 시스템 프롬프트에 세 섹션을 추가합니다. `# User workflow first`는 CLAUDE.md 우선, 스킬 먼저 확인, 완료 보고 전에 가장 좁은 검사 실행을 안내합니다. `# Tool routing`은 필요한 도구가 없으면 셸보다 ToolSearch로 먼저 찾게 하고, `# Shell commands (j-cc)`는 exec 사용법을 알립니다. 스킬 목록 머리말에는 "작업 전에 목록과 대조해 맞는 스킬을 먼저 부르고, 키워드만 겹치면 부르지 않는다"는 규칙을 넣습니다. Bash·PowerShell 설명 끝에는 위 차단 규칙을 적습니다. PowerShell은 ToolSearch 뒤로 미루고, Monitor는 처음부터 불러옵니다. |
| 응답 언어 | `language` 설정이 도구 호출 사이의 짧은 메모에도 적용된다고 덧붙입니다. 메인 세션의 도구 결과와 대화 중간 알림, 사용자가 보내지 않은 프롬프트에도 응답 언어를 다시 알립니다. 응답이 거의 영문자이면(코드·경로·URL을 빼고 20자 이상) CC 내부 모델이 설정 언어로 썼는지 판정합니다. 아니라고 판정하면 토스트로 알리고, 다음 도구 결과나 프롬프트에 경고를 붙입니다(`modelJudge`). |
| 서브에이전트 | 서브에이전트가 시작할 때 과제 끝에 파일 도구·exec·Monitor 규칙을 붙입니다. 이 경로로 규칙을 받지 못한 서브에이전트(fork 포함)는 첫 셸 결과에서 한 번 받습니다. 정의 파일의 `tools:`에 exec가 없는 에이전트는 포그라운드 셸을 막지 않습니다. |
| 컨텍스트 줄이기 | 스킬·에이전트 목록의 설명을 첫 문장(최대 120자)으로 줄이고 중복을 뺍니다. MCP 서버 안내는 서버당 600자에서 자릅니다. 도구가 8개 이상인 MCP 서버는 지연 도구 목록을 한 줄로 묶습니다. `total_tokens_reminder`를 지우고, Claude in Chrome 섹션을 짧은 버전으로 바꿉니다. `limit` 없이 텍스트 파일을 Read하면 500줄까지만 읽고 나머지를 읽는 방법을 알려 줍니다. `head_limit` 없는 Grep은 결과를 100개로 제한합니다. |

## 설치

```
/plugin marketplace add j-token/j-cc
/plugin install j-cc@j-cc
```

hooks module API를 쓰므로 Claude Code 2.1.301 이상이 필요합니다.

## 설정

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `modelJudge` | `true` | 규칙으로 판단하지 못한 Bash·PowerShell 백그라운드 명령, 우회 주석의 이유, 응답 언어 이탈을 CC 내부 모델로 판정합니다. 끄면 결정적 규칙만 쓰고, 우회 주석은 검토 없이 통과하며, 응답 언어 이탈도 검사하지 않습니다. |
| `blockChaining` | `false` | 따옴표 밖의 `&&`, `\|\|`, `;`로 명령을 이은 호출을 막습니다. |

## 우회

잘못 막힌 명령은 이유를 적은 주석을 붙여 다시 실행합니다. 이전 플러그인 표식 `# use-right-tool:allow:`도 인식합니다.

```
grep -c MAGIC app.exe # j-cc:allow: Grep 도구는 바이너리 파일 안을 검색하지 않음
```

규칙에 막혔을 명령에 주석이 붙으면, CC 내부 모델(Haiku)이 막은 규칙, 명령, 이유를 보고 셸이 정말 필요한지 판정합니다.
- 이유가 막연하거나 편의 때문이거나 안내한 도구로 할 수 있는 일이면 `Bypass rejected`로 막고, 대신 쓸 도구나 방법을 한 문장으로 안내합니다.
- 판정은 명령별로 기억합니다.
- 규칙에 막히지 않는 명령은 검토하지 않습니다. Bash·PowerShell 호출이면 결과에 주석이 필요 없었다고 알립니다. 주석을 붙여도 포그라운드 Bash는 허용되지 않습니다.
- `modelJudge`를 껐거나 모델이 답하지 못하면 예전처럼 주석을 믿고 통과시킵니다.

j-cc는 작업 흐름을 돕는 도구이며 보안 경계가 아닙니다.

## 제한

- 조직이 관리하는 Claude Code에서는 `prompt.attachment`와 `prompt.compose` 훅이 사용자가 설치한 플러그인에서 실행되지 않습니다. 이 경우 셸 차단과 도구 설명 보강만 동작합니다.
- 규칙은 근사 판단입니다.
- 서브에이전트에 exec가 있는지는 정의 파일에서 읽습니다. 프로젝트의 `.claude/agents/<이름>.md`를 먼저 보고, 없으면 `~/.claude/agents/`를 봅니다. 플러그인 에이전트는 exec가 있다고 봅니다.
- exec는 Bash 도구로 명령을 실행하므로, 샌드박스를 켜면 샌드박스가 적용됩니다. 다만 실제로 샌드박스를 켠 상태에서는 확인하지 않았습니다. 2.1.316의 Windows 샌드박스는 기능 플래그 뒤에 있습니다. 서브에이전트처럼 Claude Code가 백그라운드 시간을 제한하는 곳에서는, 그 한도(기본 10분)까지 끝나지 않은 작업이 Bash `run_in_background`와 똑같이 멈춥니다.
- exec나 poll이 기다리는 동안 Esc를 누르는 경우는 대화형 세션에서 확인하지 않았습니다.
- `blockChaining`을 켜면, 체이닝 판별은 따옴표만 보는 단순한 방식이라 `for …; do …; done`, PowerShell `{ …; … }` 블록 안의 `;`도 막습니다. 이런 스크립트는 scratchpad에 파일로 쓰고 그 파일을 실행하게 안내합니다.
- 파일 보기와 다른 명령을 이은 체인(`head f && wc -l f`)은 파일 보기 규칙에 걸리지 않습니다. 이 규칙은 호출 전체가 보기·검색뿐일 때만 막습니다.
- exec의 권한은 같은 명령의 Bash/PowerShell 판정을 따릅니다. 그 판정이 `ask`이거나, auto mode 분류기가 Bash 판정을 내지 않아 거부한 경우이면 엔진이 exec 자체에 내린 판정을 그대로 씁니다. 그래서 auto mode에서는 분류기가 판단하고, 기본 모드에서 "항상 허용"을 고르면 그 규칙이 남습니다. exec 전체를 허용 규칙에 넣으면, Bash였다면 물었을 명령도 묻지 않고 실행됩니다.
- exec가 부르는 Bash 호출은 권한을 다시 확인하지 않습니다. 같은 명령의 Bash/PowerShell 판정을 따르는 exec 자신의 확인이 유일한 관문입니다. 다른 플러그인의 Bash 훅은 이 호출에도 적용됩니다. settings.json의 `Bash`/`PowerShell` PreToolUse 훅이 적용되는지는 확인하지 않았습니다. stdin이 닫힌 채 실행하므로 대화형 프롬프트는 쓸 수 없습니다.
