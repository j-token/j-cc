# j-cc

Claude Code에서 Claude 모델(특히 Opus 5.5)이 **전용 도구를 쓰고, 사용자 지침과 스킬을 따르고, 오래 걸리는 명령을 기다리지 않도록** 하네스를 조정하는 플러그인입니다. 외부 모델이나 API 키 없이 Claude Code 안에서만 동작합니다.

[English](README.md)

## 왜 필요한가

Claude Code 2.1.301을 조사한 결과 다음 사실을 확인했습니다.

- Claude Code는 **Opus 5.5에만 "bash-first" 실험(`thrifty_sonic`)을 강제로 켭니다.** 이 실험이 켜지면 두 가지가 바뀝니다.
  - Bash 도구 설명에서 "find, grep, cat, head, sed 대신 전용 도구를 쓰라"는 `IMPORTANT` 경고가 빠집니다.
  - auto mode에서 "cat, head, sed -n으로 읽고 grep, find로 검색하고 sed나 heredoc으로 고쳐도 된다. 선택은 너에게 있다(The choice is yours)"는 리마인더가 붙습니다.
- 프록시로 연결한 GPT 모델은 Claude Code가 모르는 모델이라 이 실험이 꺼져 있습니다. 그래서 같은 하네스에서도 GPT 모델이 전용 도구를 더 잘 씁니다.
- 2026-09-10 ~ 11-02의 세션 기록 3,581개(대화형 CLI 세션만)에서, j-cc를 쓰기 시작한 10월 16일 이후 Opus 메인 세션을 j-cc 사용 여부로 나눠 비교했습니다. 세션마다 작업이 달라서 차이를 모두 j-cc 효과로 볼 수는 없습니다. 조사 방법, 전체 표, 변경의 근거로 삼은 논문([arXiv:2609.00006](https://arxiv.org/html/2609.00006v1))은 [docs/harness-engineering-evidence.md](docs/harness-engineering-evidence.md)에 있습니다.

| 지표 (Opus, 메인 세션) | j-cc (38) | 미사용, 10/16 이후 (120) |
|---|---|---|
| 셸 100회당 파일 보기 / 검색 | 3.3 / 1.8 | 8.0 / 9.2 |
| 셸 1,000회당 60초 넘는 포그라운드 명령 | 11.5 | 28.6 |
| 셸 1회당 포그라운드 대기 | 4.5초 | 8.8초 |
| 마지막 수정 뒤 검사 없이 끝난 코드 수정 턴 | 6.7% | 14.5% |

- j-cc를 쓴 세션의 서브에이전트는 여전히 셸 100회당 12.7 / 9.4번 셸로 파일을 보고 검색했습니다. 메인 세션의 약 4~5배이고 차단도 2배 넘게 당했습니다. 메인 시스템 프롬프트의 섹션이 서브에이전트에 닿는다는 보장이 없어서, 이제 서브에이전트는 시작할 때 규칙을 받습니다.

## 하는 일

| 기능 | 방법 |
|---|---|
| bash-first 실험 끄기 | 세션 시작 시 `CLAUDE_CODE_THRIFTY_SONIC=0`을 설정합니다. 엔진이 이 변수를 가장 먼저 읽으므로 문구 매칭에 의존하지 않습니다. 2.1.301에서 확인했고 2.1.316에서도 같습니다. 사용자가 이미 값을 정했다면 건드리지 않습니다. |
| 도구 설명 보강 | Bash와 PowerShell 설명 끝에 전용 도구와 `run_in_background` 사용 지침을 덧붙입니다. |
| 시스템 프롬프트 보강 | `# User workflow first` 섹션(CLAUDE.md 우선, 스킬 먼저 확인, 코드 변경을 완료라고 보고하기 전에 가장 좁은 검사를 돌리고 못 했으면 그렇다고 쓰기)과 `# Tool routing` 섹션을 추가합니다. 필요한 도구가 목록에 없으면 셸로 넘어가기 전에 ToolSearch로 찾도록 안내합니다. |
| 스킬 사용 | 스킬 목록 머리말과 `# User workflow first` 섹션에 "작업을 시작하기 전에 목록과 대조하고, 설명이 작업에 맞는 스킬을 먼저 호출한다. 키워드만 겹치면 부르지 않는다"는 규칙을 넣습니다. 목록의 설명은 첫 문장으로 줄이고 중복을 없앱니다. |
| 중간 보고 언어 | `language` 안내에 "도구 호출 사이의 짧은 진행 보고도 설정 언어로 쓴다"는 문장을 덧붙입니다. 모델은 영어 도구 결과나 하네스 알림 바로 뒤에서 짧은 보고를 영어로 쓰는 경향이 있어서, 메인 세션의 모든 도구 결과 뒤와 하네스가 대화 중간에 끼워 넣는 알림(작업 완료, 실행 중 들어온 메시지 등) 끝에 "`language` 값(없으면 사용자가 쓰는 언어)으로 답한다"는 한 문장을 붙입니다. |
| 응답 언어 이탈 감지 | `language`를 설정한 메인 세션에서 모델 응답의 글자가 거의 모두 ASCII 영문자이면(코드·경로·URL 제외, 20자 이상), CC 내부 작은 모델에게 그 글이 설정 언어로 쓰였는지 묻습니다. `language`는 자유 형식이라 해석을 모델에 맡깁니다. 아니라고 판정하면 다음 도구 결과에 "방금 설정 언어로 쓰지 않았다, 돌아가라"는 경고를 붙이고 토스트로 알립니다. 판정은 도구 실행과 겹쳐 돌아 기다리는 시간이 거의 없고, 실패하면 경고하지 않습니다. 도구 호출 없이 끝난 최종 답변은 다음 턴의 첫 도구 결과에서 경고합니다. `modelJudge`를 끄면 함께 꺼집니다. |
| 셸 오용 차단 | 셸로 파일을 보기·검색·쓰기·수정하면 막고 Read, Grep, Glob, Write, Edit로 안내합니다. |
| 명령 체이닝 차단 | 따옴표 밖의 `&&`, `\|\|`, `;`로 명령을 이은 Bash·PowerShell·exec 호출을 막고, 명령을 하나씩 나눠 실행하라고 안내합니다. 파이프(`\|`)와 백그라운드(`&`), heredoc 본문은 검사하지 않습니다. 막히기 전에 알 수 있게 Bash·PowerShell 설명 끝에 금지 사실을 적습니다. 기본 PowerShell 설명이 `cmd1 && cmd2`를 권하기 때문입니다. `blockChaining` 옵션으로 끌 수 있습니다. |
| 루프·대기 차단 | `tail -f`, 무한 루프, 포그라운드 폴링·대기, 포그라운드 dev 서버를 막고 Monitor, `run_in_background`, `/loop`, `CronCreate`로 안내합니다. |
| 오래 걸리는 명령의 백그라운드 전환 | 설치, Docker 빌드, 학습·평가 스크립트, 120초보다 긴 `timeout`, 이전에 45초 이상 걸린 명령은 자동으로 `run_in_background: true`로 실행하고, 기다리지 말고 다른 일을 하라고 알립니다. 메인 세션에만 적용합니다. 시스템 프롬프트의 `# Automatic backgrounding (j-cc)` 섹션이 이 동작을 미리 알려, 완료 알림 전에는 결과에 의존하는 단계를 실행하지 않게 합니다. |
| exec / poll 도구 | Codex의 `exec_command`/`write_stdin`처럼 동작하는 도구 두 개를 추가합니다. `mcp__j-cc__exec`는 명령을 시작하고, 명령이 아직 실행 중이어도 5~8초 안에 그때까지의 출력과 `session_id`를 돌려줍니다. `mcp__j-cc__poll`은 이어서 새 출력을 읽거나 `terminate: true`로 명령을 멈춥니다. 설정할 것은 없습니다. exec는 같은 명령의 Bash/PowerShell 권한 규칙을 따르고, poll은 권한을 묻지 않으며, j-cc의 셸 오용 차단도 똑같이 적용됩니다. Git Bash 경로는 `CLAUDE_CODE_GIT_BASH_PATH`를 먼저 보고 없으면 스스로 찾습니다. |
| 서브에이전트 맥락 | 서브에이전트가 시작할 때 과제 프롬프트 끝에 j-cc 규칙을 붙입니다. 파일은 Read, Grep, Glob, Edit, Write로 다루고(셸 파일 명령은 막힘), `blockChaining`이 켜져 있으면 셸 명령은 호출마다 하나씩 실행하며, 서브에이전트에는 자동 전환이 적용되지 않으므로 결과가 필요한 명령은 포그라운드로, 백그라운드로 돌렸다면 끝나기 전에 Monitor로 기다리라는 내용입니다. fork는 부모의 맥락을 이어받으므로 건드리지 않고, 시작할 때 규칙을 받지 못한 서브에이전트는 첫 셸 결과에서 한 번 받습니다. 느린 명령 안내도 메인과 서브에이전트에 다르게 줍니다. |
| CC 내부 모델 판정 | 규칙으로 정하지 못한 명령은 Claude Code의 `$.model`(Haiku)로 판정합니다. 명령이나 실행 스크립트에 루프·대기·서버 단서가 있을 때만 호출하며, 결과는 명령별로 캐시합니다. 판정 라벨은 `quick`, `long_job`, `wait_poll`, `endless`, `server`입니다. |
| 회귀 감지 | 환경변수를 설정했는데도 셸 우선 리마인더가 다시 나타나면 토스트로 알리고, 예비로 해당 문단을 바꿉니다. |

## 설치

```
/plugin marketplace add j-token/j-cc
/plugin install j-cc@j-cc
```

hooks module API를 쓰므로 Claude Code 2.1.301 이상이 필요합니다.

## 설정

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `modelJudge` | `true` | 애매한 명령, 우회 주석의 이유, 응답 언어 이탈을 CC 내부 모델로 판정합니다. 끄면 결정적 규칙만 쓰고, 우회 주석은 검토 없이 통과하며, 응답 언어 이탈도 검사하지 않습니다. |
| `blockChaining` | `true` | 따옴표 밖의 `&&`, `\|\|`, `;`로 명령을 이은 호출을 막습니다. |

## 우회

잘못 막힌 명령은 이유를 적은 주석을 붙여 다시 실행합니다. 이전 플러그인 표식 `# use-right-tool:allow:`도 인식합니다.

```
grep -c MAGIC app.exe # j-cc:allow: Grep 도구는 바이너리 파일 안을 검색하지 않음
```

규칙에 막혔을 명령에 주석이 붙으면, CC 내부 모델(Haiku)이 막은 규칙, 명령, 이유를 보고 셸이 정말 필요한지 판정합니다.
- 이유가 막연하거나 편의 때문이거나 안내한 도구로 할 수 있는 일이면 `Bypass rejected`로 막고, 대신 쓸 도구나 방법을 한 문장으로 안내합니다.
- 판정은 명령별로 기억합니다.
- 규칙에 막히지 않는 명령(포그라운드 유지용 주석 등)은 묻지 않고 통과합니다.
- `modelJudge`를 껐거나 모델이 답하지 못하면 예전처럼 주석을 믿고 통과시킵니다.

j-cc는 작업 흐름을 돕는 도구이며 보안 경계가 아닙니다.

## 제한

- 조직이 관리하는 Claude Code에서는 `prompt.attachment`와 `prompt.compose` 훅이 사용자가 설치한 플러그인에서 실행되지 않습니다. 이 경우 셸 차단, 도구 설명 보강, 백그라운드 전환, 환경변수 설정만 동작합니다.
- `CLAUDE_CODE_THRIFTY_SONIC`은 비공개 실험 변수라 이후 빌드에서 바뀔 수 있습니다. 그런 일이 생기면 회귀 감지 토스트가 알려 줍니다.
- 규칙은 근사 판단입니다. 실행 시간 기록은 명령 키(`npm test`, `cargo build`, `python train.py` 등) 단위로 묶입니다.
- 체이닝 판별은 따옴표만 보는 단순한 방식이라 `for …; do …; done`, PowerShell `{ …; … }` 블록 안의 `;`도 막습니다. 이런 스크립트는 scratchpad에 파일로 쓰고 그 파일을 실행하게 안내합니다.
- exec의 권한은 같은 명령의 Bash/PowerShell 판정을 따릅니다. 그 판정이 `ask`이면 엔진이 exec 자체에 내린 판정을 그대로 씁니다. 그래서 auto mode에서는 분류기가 판단하고, 기본 모드에서 "항상 허용"을 고르면 그 규칙이 남습니다. exec 전체를 허용 규칙에 넣으면, Bash였다면 물었을 명령도 묻지 않고 실행됩니다.
- exec는 settings.json의 `Bash`/`PowerShell` PreToolUse 훅을 거치지 않습니다. 권한 규칙과 j-cc 차단만 적용됩니다. 호출마다 새 셸을 열고 stdin을 닫으므로 대화형 프롬프트는 쓸 수 없습니다.
